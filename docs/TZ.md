# Техническое задание — «Карьера РТУ МИРЭА»

Версия 1.0 · Статус: на согласование

## 1. Суть продукта

Мобильное приложение (Android + iOS) — агрегатор вакансий, стажировок, событий и мероприятий РТУ МИРЭА и компаний-партнёров.

**Студент:** без регистрации и без аккаунта. Заходит → смотрит ленту → фильтрует по типу / кампусу / институту / направлению / тегам / компаниям → открывает карточку с подробностями → уходит по внешней ссылке на регистрацию или форму заявки. Персональные данные (профиль-опрос, избранное) живут **только локально** на устройстве.

**Авторы контента:** отделы вуза и компании-партнёры создают карточки через веб-админку. Публикация в приложении возможна **только** после одобрения модераторской службой вуза.

**Модерация:** ассистенты проверяют и отклоняют, главный модератор — единственный, кто публикует. Супер-админ (один) — корневая роль, управляет модераторами, организациями и доступами.

## 2. Ролевая модель

| Роль | Права |
|---|---|
| Аноним (студент) | Чтение только `published`. Просмотры/избранное — через RPC-счётчики. |
| Супер-админ | Всё. Создаёт организации (отделы вуза, партнёров), назначает org_admin и модераторов. Единственный экземпляр. |
| Главный модератор | Видит все посты всех статусов. **Единственный, кто переводит `reviewed_ready → published`**. Управляет `is_featured` / `priority_weight` / целевой аудиторией. |
| Ассистент модератора | Проверяет посты: `pending_review → reviewed_ready` или `rejected` (с причиной). Не публикует. |
| Админ организации (org_admin) | Отдел вуза или компания: CRUD своих постов, управление сотрудниками своей организации, редактирование профиля организации. |
| Сотрудник организации (org_member) | Создаёт и редактирует посты своей организации. Не управляет сотрудниками. |

Модераторская служба — отдельная группа, не привязанная ни к одной организации (`organization_id = null`), стоит над всеми отделами и партнёрами; над ней — только супер-админ.

## 3. Пользовательские сценарии (студент)

1. **Первый запуск:** 4 шага мини-опроса (кампус → институт → курс/уровень → интересы-теги). Пропускаемо, редактируемо позже. Данные не покидают устройство.
2. **Главная:** hero-карусель приоритетного (поднято главным модератором) → чипсы быстрых фильтров → «Для вас» (локальный скоринг по профилю) → «Новое» (хронология).
3. **Каталог:** переключатель «Вуз / Партнёры» + панель фильтров (тип, кампус, институт, формат, компания, теги). Цель вкладки — подбор по намерению: студенческая жизнь vs карьера.
4. **Карточка:** обложка, заголовок, тип, организатор, даты, описание (rich text), счётчики, теги, закреплённая внизу кнопка «Подать заявку / Зарегистрироваться» → системный браузер.
5. **Избранное:** локальный список, работает офлайн; постановка/снятие синхронно дергает RPC-счётчик на бэке.
6. **Другое:** редактирование профиля-опроса, тема (светлая/тёмная/системная), о приложении, контакты карьерного центра.

## 4. Сценарии авторов и модерации (веб-админка)

1. Сотрудник партнёра создаёт пост → «Отправить на модерацию» (`pending_review`).
2. Ассистент видит очередь `pending_review` → «Проверено» (`reviewed_ready`) или «Отклонить» (`rejected` + необязательная внутренняя заметка).
3. Главный модератор видит `reviewed_ready` → при желании «В приоритет» (featured) → «Опубликовать» (`published`).
4. Пост появляется в приложении немедленно (realtime-подписка на таблицу).
5. Счётчики «просмотры / заинтересовались» видны автору и модераторам, обновляются в реальном времени.

Демонстрационный сценарий (для защиты): админка на проекторе публикует карточку → телефон в руках обновляет ленту → тап «в избранное» → счётчик в админке растёт без перезагрузки.

## 5. Нефункциональные требования

- Адаптивность: от 320 dp (SE) до планшетов (>600 dp — двухколоночная сетка).
- iOS-эстетика: матовое стекло, squircle-скругления, диффузные тени, пружинные анимации, haptic-отклик; плавающий закруглённый док у нижнего края с учётом home-indicator.
- Офлайн: избранное и кэш ленты читаются без сети; счётчики — fire-and-forget с локальной очередью.
- Скорость: холодный старт < 2 с, первая лента (кэш) мгновенно.
- Русский язык интерфейса (единственный на MVP).

## 6. Границы MVP (что НЕ делаем)

- Push-уведомления, календарь/напоминания, отклики внутри приложения, чаты.
- Аналитика глубже счётчиков просмотров/избранного.
- Мультивузность (архитектура допускает, UI — нет).
- Полноценная админка в мобильном приложении — только веб.
- Антифрод счётчиков глубже дедупликации «1 просмотр на устройство на сессию».
