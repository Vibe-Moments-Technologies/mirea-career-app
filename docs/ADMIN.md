# Веб-админка — «Карьера РТУ МИРЭА»

Назначение: **презентационный** инструмент, показать полный цикл «автор создал → модераторы проверили → главный опубликовал → карточка в телефоне». Не полноценная CMS.

## 1. Стек и запуск

- Vite + TypeScript, `@supabase/supabase-js`, без UI-фреймворка (чистый TS + CSS-переменные, минимальный роутинг по hash).
- `.env`: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`.
- `pnpm i && pnpm dev` → localhost-страница. Деплой (по желанию) — статика на Supabase Storage / любой хостинг.

Одна SPA, вход по email+паролю (`supabase.auth.signInWithPassword`). Роли читаются из `profiles`. Никакой сервис-роли в браузере.

## 2. Экраны по ролям

### Вход
Форма email/пароль. После входа — роль определяет домашний экран и пункты меню. Демо-ссылки «Войти как …» (подставляют email/пароль) — для быстрого переключения на защите.

### Общее для всех авторизованных
- Верхняя панель: логотип, имя пользователя, роль-бейдж, выход.
- Левое меню (по правам): «Мои посты» (авторы), «Модерация» (ассистент+главный+супер), «Организации» (супер), «Пользователи» (супер), «Статистика» (все — счётчики).

### Рабочее место автора (org_admin / org_member)
- Список своих постов (таблица: обложка, заголовок, тип, статус-бейдж, дата, 👁/🔖).
- Кнопка «Создать пост» → форма: заголовок, тип, формат, описание (textarea, Markdown), дата события, теги (ввод с запятой), целевые кампусы/институты/уровни (мультивыбор), внешняя ссылка, обложка (загрузка в Storage `media/`).
- Действия по статусу: `draft` → «Отправить на модерацию»; `rejected` → показать заметку, «В черновик и править»; `published` → «Снять с публикации» (если главный/или read-only).
- org_admin дополнительно: вкладка «Сотрудники» — пригласить (email → `auth.admin` недоступен в браузере, поэтому **упрощённо**: список сотрудников своей org + ссылка-инструкция; реальное создание пользователя — через супер-админа/seed). `ponytail:` полноценный invite-флоу (email magic link + назначение org_member) — после демо, требует edge function.

### Рабочее место ассистента (assistant_moderator)
- Очередь `pending_review` (все организации): карточки со сводкой + «Открыть на проверку».
- Экран проверки: полный предпросмотр карточки (как в приложении) → «Проверено, передать главному» (`reviewed_ready`) или «Отклонить» (модалка с причиной → `rejected` + запись в `rejection_notes`).

### Рабочее место главного модератора (main_moderator)
- Вкладка «Готовы к публикации» (`reviewed_ready`) → предпросмотр → **«Опубликовать»** (зелёная, переводит в `published`, ставит `published_at=now()`).
- Чекбокс «В карусель приоритетных» (`is_featured`) + поле «Вес» (`priority_weight`) — до публикации.
- Вкладка «Опубликованные»: снять с публикации, поменять featured/вес, править целевую аудиторию.

### Супер-админ
- Всё из главного модератора + «Организации» (CRUD: название, тип, описание, логотип) + «Пользователи» (таблица profiles: смена роли, привязка к организации). Создание самих auth-пользователей — через seed-скрипт/SQL (браузер не имеет `service_role`).

## 3. «Статистика» (счётчики)

Простая таблица по постам: 👁 views, 🔖 favorites, отсортировано по favorites. Обновляется realtime-подпиской на `posts` — для демо «ткнул в телефоне → цифра выросла в браузере».

## 4. Демонстрационный сценарий (прогон на защите)

1. Войти как `partner_emp@` → создать пост «День карьеры Яндекса» → «Отправить на модерацию».
2. Войти как `assist@` → очередь → «Проверено».
3. Войти как `chiefmod@` → «Готовы к публикации» → ✔ «В карусель» → **«Опубликовать»**.
4. Телефон (приложение, роль студента) → лента обновляется сама (realtime) → карточка в hero → тап «в избранное».
5. Браузер (`chiefmod@` → «Статистика») → 🔖 растёт 0→1 без перезагрузки.

Переключение ролей — через демо-кнопки входа (секунды), чтобы не тратить время на набор email.

## 5. Что НЕ делаем в админке на MVP

- Drag-and-drop kanban (достаточно таблиц со статус-фильтром).
- Полноценный WYSIWYG-редактор (Markdown textarea + предпросмотр).
- Invite по email, 2FA, аудит-лог действий, версионирование постов, локализация.
- Загрузка/кроп изображений — только прямой upload в Storage без обработки.
